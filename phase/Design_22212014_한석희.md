## 1. Introduction
#### a) Summary
최근 현대인의 문화 콘텐츠 소비는 영화나 책처럼 긴 시간을 두고 소비하기보다 일명 ‘숏폼’이라고 불리는 1분 내외의 강렬하고 짧은 콘텐츠 소비가 대부분을 이루고 있다. 특히, 젊은 세대를 중심으로는 인사말로 “혹시 MBTI 유형이 어떻게 되세요?”라고 말할 정도로 본인과 상대방을 알아가기 위해 성격 유형 등을 확인하는 것에 열광하는 모습을 종종 볼 수 있다. 이러한 성향인지에 대한 열풍은 “나는 어떤 사람일까?”를 넘어, “나(혹은 타인)는 불안 앞에서 어떤 선택을 내릴까?”라고 하는 궁금증을 담은 심리 탐색으로도 확장되기도 한다. 이는 수많은 사람의 심리가 실시간으로 충돌하며 이익과 손실을 만들어 내어 인간의 선택이 그대로 드러나는 자산 거래, 특히 주식 거래소(혹은 가상화폐 거래소) 에서 그 특징이 두드러진다고 생각한다. 따라서, 이러한 사회적인 흐름을 반영하여 모의 주식 시장 시뮬레이션 게임을 제안한다.

#### b) Important Point of Design
- DB 접근을 Repository 클래스로 분리하여 클래스 로직과 DB 접근 로직을 분리
- 안전을 위해, 대부분의 클래스의 속성을 getter/setter를 통해서만 접근
- Client(Router) -> Repository -> Domain 클래스 방향으로 설계

##  3. Sequence Diagram
### Use Case # 1 : Login
![](https://github.com/HanSatCode/MindStock/blob/main/phase/img/Design_Login.png?raw=true)

Player가 클라이언트의 입력한 닉네임과 비밀번호로 로그인하는 Use Case에 대한 Sequence Diagram이다. PlayerRepository의 find_by_name()을 호출하여 Player를 조회하며, 이 과정에서 Portfolio 잔고 설정, TradeRepository를 통한 거래 내역 조회, Tendency 분석, Player 객체의 생성이 이루어진다. 만약 Player가 존재하는 경우 Authorization의 login()을 호출하여 비밀번호를 검증하며, 일치하면 JWT 토큰을 반환하고, 그렇지 않으면 실패를 반환한다. 만약 Player가 존재하지 않는 경우에도 실패를 반환한다.

### Use Case # 2 : Register
![](https://github.com/HanSatCode/MindStock/blob/main/phase/img/Design_Register.png?raw=true)

Player가 클라이언트의 입력한 닉네임과 비밀번호로 회원가입하는 Use Case에 대한 Sequence Diagram이다. PlayerRepository의 is_name_exists()를 호출하여 닉네임 중복 여부를 확인한다. 닉네임이 중복되지 않는 경우, PlayerRepository의 create()를 호출하여 Player를 생성하고, Authorization의 register()를 호출하여 JWT 토큰을 발급한다. 만약 닉네임이 중복되는 경우 실패를 표시한다.

##  4. State Machine Diagram
![](https://github.com/HanSatCode/MindStock/blob/main/phase/img/Design_StateMachineDiagram.png?raw=true)
Player가 게임을 실행하면 로그인 화면이 표시된다. Player의 이름과 비밀번호를 입력해 로그인을 시도하면 Authorization 상태로 전이하여 인증을 처리하고, 성공하면 토큰을 발급해 메인 화면으로 넘어간다. 계정이 없는 Player는 회원가입 화면으로 이동해 등록을 진행할 수 있다.

메인 화면에 진입하면 서버와 실시간 통신이 시작되고, Player는 내비게이터을 통해 거래소/뉴스/포트폴리오/랭킹/투자 성향으로 페이지를 이동할 수 있다. 즉, 내비게이터를 통해 이동하는 것은 Player의 개인적인 행동에 따라 비동기적으로 이동할 수 있다는 의미이다.

거래소에 진입하면 종목 정보를 불러오는 행동이 반복적으로 일어나, 각 종목의 이름/식별코드.현재 등이 표시되고, 종목을 선택하면 Focused Stock 상태가 된다. 여기서 매수를 시도하면 Player의 정보를 읽고 잔고를 검증한 뒤, 통과하면 매수가 체결되어 보유 종목과 거래 내역이 갱신된다. 매도 또한 잔고 검증 후에 통과하면 매도가 체결되어 보유 종목과 거래 내역이 갱신된다. 갱신 후, 결과가 성공적이든 실패적이든 Focused Stock으로 복귀한다. (결과 내용은 화면에 표시한다.)

뉴스 화면에서는 생성된 뉴스의 제목/본문/영향과 해당 뉴스의 긍정/부정/중립이 함께 표시된다. 플레이어는 현재 시장에 영향을 주고 있는 뉴스와 이미 반영이 끝난 지난 뉴스를 구분해 확인하고, 이를 참고해 종목의 향후 주가 흐름을 예측하여 매수·매도 판단을 내릴 수 있다.

포트폴리오 화면에서는 자산을 불러와 총 자산과 수익률을 계산해 보여주고, 보유 종목과 각 종목의 평균 매수 단가·수량을 함께 확인할 수 있다. 이 상태에서 거래 내역 조회로 전이하면 그동안 누적된 매수·매도 기록을 볼 수 있으며, 물론 거래 내역 조회에서 다시 포트폴리오 상태로 전이할 수도 있다.

투자 성향 화면에서는 누적된 거래 데이터를 분석해 리스크 성향·투자 기간·종목 집중도·판단 기준이라는 네 가지 축의 결과를 산출하고, 이를 조합한 성향 코드와 함께 항목별 수치를 시각화하여 보여준다. 다만 분석에 필요한 거래 데이터가 일정 수치에 미치지 못하면 분석할 수 없다는 안내가 표시된다.

랭킹 화면에서는 모든 플레이어의 포트폴리오를 집계해 총 자산 기준 순위를 매겨, 게임 내 전체 플레이어의 등수와 자신의 등수를 함께 보여준다. 각 항목에는 순위와 자산뿐 아니라 해당 플레이어의 성향 코드, 거래 횟수, 승률, 수익, 주요 보유 종목 등이 함께 표시된다.

이렇게 거래소/뉴스/포트폴리오/투자 성향/랭킹 어느 화면에 있더라도 플레이어는 다시 원하는 화면으로 돌아올 수 있으며, 게임을 종료하면 진행 중이던 모든 흐름이 하나의 종료 상태로 모이며 게임이 마무리된다.

## 6. Glossary

|용어|설명|
|:---:|---|
|티커 (Ticker)|종목을 식별하는 고유한 영문 코드. 실제 증권 시장의 종목 코드 개념을 차용함|

|포지션 (Position)|특정 종목에 대한 보유 수량과 평균 매수 단가 정보를 담은 단위|

|거래세 (Trade VAT)|종목 거래 시 부과되는 세율로, 종목마다 다르게 설정됨|
|보유세 (Ownership VAT)|종목을 보유하고 있는 동안 주기적으로 부과되는 세율|
|성향 유형 코드 (Tendency Code)|Player의 투자 성향을 리스크(A/C), 투자 기간(S/L), 종목 집중도(F/D), 수익성(L/P) 4개 축의 알파벳으로 조합한 게임 고유 코드|
|공포 탐욕 지수 (Fear & Greed Index)|시장의 매수/매도 거래량을 기반으로 산출하는 시장 심리 지표|
|쿨다운 (Cooldown)|동일 종목을 연속으로 거래하지 못하도록 설정한 대기 시간|
|틱 (Tick)|시뮬레이션이 주가를 갱신하는 주기적인 시간 단위|
|봇 거래 (Bot Trading)|시장 균형 유지를 위해 시스템이 자동으로 수행하는 가상의 거래|
|상장 (Listed)|종목이 거래소에 등록되어 거래 가능한 상태가 되는 것|
|JWT (JSON Web Token)|로그인 인증에 사용되는 토큰 기반 인증 방식|
|Repository 패턴|DB 접근 로직을 도메인 클래스로부터 분리하여 별도 클래스로 관리하는 설계 패턴|
|WebSocket|서버와 클라이언트 간 실시간 양방향 통신을 가능하게 하는 프로토콜. 주가 실시간 전송에 사용함|
|LLM (Large Language Model)|대규모 언어 모델로, 본 프로젝트에서는 시장 뉴스 자동 생성에 활용함|
