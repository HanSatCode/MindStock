## 1. Introduction
#### a) Summary
최근 현대인의 문화 콘텐츠 소비는 영화나 책처럼 긴 시간을 두고 소비하기보다 일명 ‘숏폼’이라고 불리는 1분 내외의 강렬하고 짧은 콘텐츠 소비가 대부분을 이루고 있다. 특히, 젊은 세대를 중심으로는 인사말로 “혹시 MBTI 유형이 어떻게 되세요?”라고 말할 정도로 본인과 상대방을 알아가기 위해 성격 유형 등을 확인하는 것에 열광하는 모습을 종종 볼 수 있다. 이러한 성향인지에 대한 열풍은 “나는 어떤 사람일까?”를 넘어, “나(혹은 타인)는 불안 앞에서 어떤 선택을 내릴까?”라고 하는 궁금증을 담은 심리 탐색으로도 확장되기도 한다. 이는 수많은 사람의 심리가 실시간으로 충돌하며 이익과 손실을 만들어 내어 인간의 선택이 그대로 드러나는 자산 거래, 특히 주식 거래소(혹은 가상화폐 거래소) 에서 그 특징이 두드러진다고 생각한다. 따라서, 이러한 사회적인 흐름을 반영하여 모의 주식 시장 시뮬레이션 게임을 제안한다.

#### b) Important Point of Design
- DB 접근을 Repository 클래스로 분리하여 클래스 로직과 DB 접근 로직을 분리
- 대부분의 클래스의 속성을 getter/setter를 통해서만 접근
- Client(Router) -> Repository -> Domain 클래스 방향으로 설계

##  3. Sequence Diagram

### Use Case # 1 : Login
![](phase\img\...png)
Player가 클라이언트의 입력한 닉네임과 비밀번호로 로그인하는 Use Case에 대한 Sequence Diagram이다. PlayerRepository의 find_by_name()을 호출하여 Player를 조회하며, 이 과정에서 Portfolio 잔고 설정, TradeRepository를 통한 거래 내역 조회, Tendency 분석, Player 객체의 생성이 이루어진다. 만약 Player가 존재하는 경우 Authorization의 login()을 호출하여 비밀번호를 검증하며, 일치하면 JWT 토큰을 반환하고, 그렇지 않으면 실패를 반환한다. 만약 Player가 존재하지 않는 경우에도 실패를 반환한다.

### Use Case # 2 : Register
![](phase\img\...png)
Player가 클라이언트의 입력한 닉네임과 비밀번호로 회원가입하는 Use Case에 대한 Sequence Diagram이다. PlayerRepository의 is_name_exists()를 호출하여 닉네임 중복 여부를 확인한다. 닉네임이 중복되지 않는 경우, PlayerRepository의 create()를 호출하여 Player를 생성하고, Authorization의 register()를 호출하여 JWT 토큰을 발급한다. 만약 닉네임이 중복되는 경우 실패를 표시한다.

### Use Case # 3 : View Stock Info
![](phase\img\...png)
Player가 클라이언트의 내비게이터에서 거래소를 누르거나, 로그인 시 거래소에 접속하여 종목 목록을 조회하는 Use Case에 대한 Sequence Diagram이다. StockRepository의 find_all()을 호출하여 모든 종목에 대해서 정보를 조회한다. 그리고, 각 Stock 객체에서 ticker, name, sector, current_price, initial_price, open_price, ownership_vat를 순차적으로 조회하여 클라이언트에 표시한다.

### Use Case # 4 : Buy Stock
![](phase\img\...png)
Player가 View Stock Info를 통해 표시된 종목 중, 선택한 종목에 대해 매수 기능을 하는 Use Case에 대한 Sequence Diagram이다. 만약 수량이 0 이하인 경우 실패를 반환한다. 만약 수량이 유효한 경우 토큰에서 Player 이름을 추출하고 쿨다운(대기시간)을 확인한 뒤, StockRepository와 PlayerRepository에서 종목과 Player의 정보를 조회한다. 이후 Stock에서 현재가를 조회하여 Portfolio의 buy() 메소드를 호출하며, 매수 성공 시 거래 내역을 저장하고 SimulationEngine에 매수량을 누적하여 가격에 영향을 준다. 매수 실패 시 잔고 부족 메시지를 표시한다.

### Use Case # 5 : Sell Stock 
![](phase\img\...png)
Player가 View Stock Info를 통해 표시된 종목 중, 선택한 종목에 대해 매도 기능을 하는 Use Case에 대한 Sequence Diagram이다. Buy Stock과 동일한 흐름으로 진행되며, Portfolio의 sell() 메소드를 호출하여 매도를 처리한다. 매도 성공 시 거래 내역을 저장하고 SimulationEngine에 매도량을 누적하여 가격에 영향을 준다. 매도 실패 시 보유 수량 부족 메시지를 표시한다.

### Use Case # 6 : View News 
![](phase\img\...png)
Player가 클라이언트의 내비게이터에서 뉴스를 누를 때, 뉴스 목록을 조회하는 Use Case에 대한 Sequence Diagram이다. NewsRepository의 find_all()을 호출하여 뉴스 목록을 조회한다. 조회된 각 News 객체에서 ticker, outlook, title, description, impact, timestamp, reveal_time, is_real을 순차적으로 조회하여 클라이언트에 표시한다.

### Use Case # 7 : View Portfolio
![](phase\img\...png)
Player가 클라이언트의 내비게이터에서 포트폴리오를 누를 때, Player의 포트폴리오를 조회하는 Use Case에 대한 Sequence Diagram이다. 토큰에서 Player 이름을 추출하고 PlayerRepository와 StockRepository에서 Player와 종목 정보를 조회한다. Portfolio에서 보유 포지션을 가져오고 각 StockPosition에서 수량과 평균 매수 단가를 조회한다. 이후 총 자산과 잔고를 계산하여 클라이언트에 표시한다.

### Use Case # 8 : View Trade History
![](phase\img\...png)
Player가 View Portfolio 후 내비게이터에서 '거래 내역'을 누를 때, Player의 거래 내역을 조회하는 Use Case에 대한 Sequence Diagram이다. 토큰에서 Player 이름을 추출하고 PlayerRepository에서 Player를 조회한다. Player 객체에서 거래 내역 목록을 가져오고 각 TradeHistory 객체에서 ticker, action, quantity, price, total_cost, timestamp를 순차적으로 조회하여 클라이언트에 표시한다.

### Use Case # 9 : View Ranking
![](phase\img\...png)
Player가 클라이언트의 내비게이터에서 '랭킹'을 누를 때, 전체 Player의 순위를 조회하는 Use Case에 대한 Sequence Diagram이다. PlayerRepository에서 모든 Player를, StockRepository에서 모든 종목의 현재가를 조회한다. 각 Player마다 Portfolio에서 총 자산과 수익률을, Tendency에서 수익성과 성향 코드를, Portfolio에서 보유 포지션을 조회한다. 보유 수량이 가장 많은 종목 2개를 추출한 뒤 총 자산 기준으로 정렬하여 순위를 클라이언트에 표시한다.

### Use Case # 10 : View Investment Tendency
![](phase\img\...png)
Player가 클라이언트의 내비게이터에서 '투자 성향'을 누를 때, 투자 성향을 분석하여 조회하는 Use Case에 대한 Sequence Diagram이다. 토큰에서 Player 이름을 추출하고 PlayerRepository에서 Player를 조회한다. 거래 횟수가 25회 미만인 경우 분석 불가 메시지를 표시하며, 25회 이상인 경우 Tendency 객체에서 성향 코드, 리스크, 투자 기간, 집중도, 수익성, 평균 보유 시간, 보유 종목 수를 조회하여 클라이언트에 표시한다.
